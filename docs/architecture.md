# Архитектура

```text
Браузер на localhost
        │ multipart upload
        ▼
FastAPI ─── API статуса и скачивания
        │
        ▼
JobManager: память + очередь из одного worker
        │
        ▼
FFmpeg → WAV 16 kHz mono
        │
        ▼
MLX Whisper на Apple Silicon
        │
        ▼
TXT / Markdown / JSON / SRT
```

## Жизненный цикл задания

1. FastAPI проверяет расширение и сохраняет файл во временный каталог экземпляра приложения.
2. `JobManager` помещает идентификатор задания в очередь в оперативной памяти.
3. Единственный worker извлекает аудио, при необходимости явно скачивает модель и запускает
   MLX Whisper в отдельном процессе.
4. Результат преобразуется в четыре выходных формата.
5. Браузер получает состояние через периодический `GET /api/jobs/{id}`.
6. Исходный файл удаляется после успешного завершения.
7. Оставшиеся временные результаты удаляются при штатной остановке сервера.

## Защита от циклических повторов

Whisper обрабатывает длинную запись окнами примерно по 30 секунд. Передача текста предыдущего
окна в следующее иногда создаёт самоподдерживающийся repetition loop. Приложение запускает
Whisper с `condition_on_previous_text=False` и более строгим
`compression_ratio_threshold=2.0`. Это немного уменьшает контекстную связность между соседними
окнами, но заметно снижает риск длинных искусственных повторов. Готовый текст механически не
«чистится», поэтому настоящие повторения говорящего сохраняются.

Отдельный процесс распознавания позволяет действительно остановить вычисления кнопкой «Отменить»,
а не только скрыть задание в интерфейсе. При отмене процесс завершается и временный исходник
удаляется.

## Почему один worker

Одновременная загрузка нескольких крупных моделей создаёт конкуренцию за unified memory и
обычно ухудшает скорость на одном Mac. Последовательная очередь предсказуема и оставляет
веб-интерфейс отзывчивым.

## Хранение состояния

Базы данных нет. Словарь заданий и очередь существуют только в памяти процесса. Перезапуск
сервера сбрасывает задания и историю — это намеренное свойство локального инструмента.

## Хранение моделей

Модели сохраняются в каталоге `models/` в корне проекта. Конкретные каталоги имеют вид
`models--mlx-community--whisper-large-v3-turbo`. Кэш не удаляется при остановке приложения:
модель скачивается один раз и переиспользуется в следующих заданиях.

Каталог можно переопределить переменной `TRANSCRIBER_MODELS_DIR`. Удаление доступно из
веб-интерфейса и разрешено только для трёх моделей, которыми управляет приложение. Модель,
используемую активным заданием, удалить нельзя.

## Границы доверия

- сервер слушает `127.0.0.1` по умолчанию;
- разрешены Host-заголовки `localhost` и `127.0.0.1`;
- имена загрузок очищаются до базового имени;
- путь скачивания выбирается только из заранее сформированной карты результатов;
- frontend не загружает код, шрифты или аналитику из интернета.
